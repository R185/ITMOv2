# event-reporting Specification

## Purpose
Поведение снапшота прогона в части событий: какие события попадают в вывод и как потребитель может запросить только нужное подмножество, не разбирая массив самостоятельно.

## Requirements

### Requirement: Запрос подмножества событий

Headless-вывод MUST allow the caller to запросить подмножество событий последнего действия, перечислив их имена через запятую. Имена сравниваются точно, регистр значим; пробелы вокруг запятых и по краям списка не являются частью имени.

#### Scenario: Запрошено одно событие

- **WHEN** прогон выполняется с `--events clear:tetris` и последнее действие дало события `["clear:tetris","combo"]`
- **THEN** в JSON поле `events` равно `["clear:tetris"]`, остальные ключи снапшота не изменены

#### Scenario: Запрошено несколько событий

- **WHEN** прогон выполняется с `--events "clear:single, clear:tetris"` и последнее действие дало события `["clear:single","clear:tspin_single"]`
- **THEN** в JSON поле `events` равно `["clear:single"]`, а `clear:tspin_single` отфильтровано

#### Scenario: Порядок вывода и дубликаты в списке

- **WHEN** запрошены `--events "combo,clear:tetris,combo"` и снапшот содержит события `["clear:tetris","combo"]`
- **THEN** в JSON поле `events` равно `["clear:tetris","combo"]` — порядок исходного набора сохранён, повтор имени в списке не дублирует элемент

### Requirement: Формы имён событий

Имя события MUST совпадать с точной строкой, которая лежит в `events`: действия без префикса (`hard_drop`, `hold`, `left`…), события линий с префиксом `clear:` (`clear:single`, `clear:tetris`, `clear:tspin_mini`…) и мета-события (`combo`, `b2b`, `perfect_clear`). Полный перечень (22 имени) MUST быть доступен потребителю.

#### Scenario: Форма без префикса не является именем

- **WHEN** запрошено `--events tetris`, а в снапшоте такое событие выглядит как `clear:tetris`
- **THEN** это неизвестное имя: код 2, в перечне допустимых есть `clear:tetris`

#### Scenario: Перечень имён доступен потребителю

- **WHEN** выполняется `--help` или возникает ошибка неизвестного имени
- **THEN** вывод содержит полный перечень 22 имён

### Requirement: Обратная совместимость без флага

Без флага `--events` вывод MUST оставаться прежним: в `events` попадают все события последнего действия в существующем порядке.

#### Scenario: Флаг не указан

- **WHEN** прогон выполняется без `--events`
- **THEN** JSON и ASCII-вывод совпадают с выводом до появления флага при тех же `--seed`, `--script`, `--ticks`

### Requirement: Ошибки в списке событий

Некорректный список событий MUST приводить к ошибке аргументов: код выхода 2, сообщение в stderr с перечнем допустимых имён событий, прогон партии не выполняется.

#### Scenario: Неизвестное имя

- **WHEN** прогон выполняется с `--events foo`
- **THEN** процесс завершается с кодом 2, в stderr есть имя `foo` и перечень допустимых имён, JSON в stdout не печатается

#### Scenario: Пустой список

- **WHEN** прогон выполняется с `--events ""`
- **THEN** процесс завершается с кодом 2 и сообщением о пустом списке событий

#### Scenario: Пустое имя внутри списка

- **WHEN** список содержит пустой элемент (`--events "clear:single,,combo"`)
- **THEN** это ошибка аргументов с кодом 2 и сообщением о пустом имени

#### Scenario: Имя не из словаря событий

- **WHEN** в списке указано имя, которое система не порождает (`--events tetris` вместо `clear:tetris`)
- **THEN** это считается неизвестным именем и даёт код 2, а не молчаливое отсеивание

### Requirement: Пустой результат фильтрации

Отсутствие совпадений MUST NOT быть ошибкой: прогон считается успешным, поле `events` содержит пустой массив.

#### Scenario: Запрошено событие, которого не было

- **WHEN** прогон выполняется с `--events perfect_clear` и в последнем действии его не было
- **THEN** код выхода 0, в JSON поле `events` равно `[]`, остальные ключи снапшота заполнены как обычно

#### Scenario: Событие было раньше, но не последним действием

- **WHEN** в партии был `hold`, а последним действием стал `hard_drop`, и запрошено `--events hold`
- **THEN** код выхода 0, поле `events` равно `[]` — снапшот описывает только последнее действие

### Requirement: Независимость от режима вывода

Фильтр событий MUST влиять только на поле `events` JSON-снапшота и MUST NOT менять остальные поля, ASCII-представление и коды выхода успешного прогона.

#### Scenario: Фильтр вместе с ASCII

- **WHEN** прогон выполняется с `--ascii --events clear:tetris`
- **THEN** ASCII-поле печатается как обычно (события в нём не отображаются), код выхода 0

#### Scenario: Фильтр вместе с усечённым JSON

- **WHEN** прогон выполняется с `--no-board --events hold`
- **THEN** массив `board` отсутствует как и раньше, `board_hash` присутствует, поле `events` отфильтровано

#### Scenario: Фильтр не меняет счёт и поле

- **WHEN** сравниваются два прогона с одинаковыми `--seed`, `--script`, `--ticks`, отличающиеся только `--events`
- **THEN** `score`, `lines`, `level`, `holes`, `board_hash`, `tick` совпадают
