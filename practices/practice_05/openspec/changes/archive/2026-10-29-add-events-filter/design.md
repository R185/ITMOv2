# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/event-reporting/spec.md`.

Текущее состояние, которое определяет подход:
- События — `std::vector<std::string> events_` в `Game`, очищается на любом действии кроме `Tick` (`src/core/game.cpp:198-201`), поэтому снапшот содержит только события последнего действия.
- Имена событий собираются из двух мест: ядро (`src/core/game.cpp`: `left`, `right`, `rotate_cw`, `rotate_ccw`, `rotate_180`, `soft_drop`, `hard_drop`, `hold`, `lock_out`, `game_over`) и подсчёт очков (`src/core/scoring.cpp`), где событие склеивается как `"clear:" + clear_label(result)` — то есть в снапшоте лежат `clear:single`, `clear:tetris`, `clear:tspin_mini` и т. п., а не «голые» метки, плюс `combo`, `b2b`, `perfect_clear`. Всего 22 имени; единого списка в коде нет. Форма с префиксом подтверждена прогоном (`clear:tspin_mini`), и именно её берёт словарь.
- Печать событий есть только в JSON (`src/core/serialize.cpp:100-105`); `render_ascii` их не показывает.
- CLI разбирает аргументы в `src/main.cpp`, ошибки аргументов идут через `argument_error` → код 2 (образец строгости — проверка токенов `--script`, `src/main.cpp:169-176`).
- `CMakeLists.txt` собирает `src/core/*.cpp` и `tests/*.cpp` через `GLOB_RECURSE ... CONFIGURE_DEPENDS`, тесты регистрируются макросом `TEST()` и подхватываются `tests/main.cpp` — новые файлы не требуют правки сборки.

## Goals / Non-Goals

**Goals:**
- Фильтрация событий как чистая функция ядра, покрытая юнит-тестами (CLI-контракт юнитами не покрывается вообще).
- Единый публичный словарь имён событий, на который опирается и проверка входа, и сообщения об ошибках.
- Нулевое влияние на поведение без флага и на остальные поля снапшота.

**Non-Goals:**
- Хранение истории событий за партию и фильтрация по времени/тику.
- Фильтр по категориям, подстрокам или регулярным выражениям.
- Отображение событий в ASCII/SDL и расширение MCP-инструментов.
- Рефакторинг существующих литералов событий в ядре (перевод `game.cpp`/`scoring.cpp` на константы) — отдельное изменение.

## Decisions

**D1. Фильтр живёт в ядре, а не в `main.cpp`.** `src/main.cpp` не входит в `tetris_tests`, поэтому логика там непроверяема юнитами. Альтернатива «разобрать список прямо в CLI» быстрее в реализации, но оставляет единственную проверку ручной.

**D2. Отдельный модуль `include/tetris/core/events.hpp` + `src/core/events.cpp`.** Словарь имён и разбор списка — самостоятельная ответственность; `game.hpp` уже импортируется везде, и складывать туда строковый протокол вывода значит смешивать состояние игры с форматом отчёта. `CMakeLists.txt` подхватит новый `.cpp` через существующий GLOB.

**D3. Неизвестное имя — ошибка, а не тихий отсев.** Тот же принцип, что у неизвестного токена `--script`: успешный прогон с опечаткой в фильтре выглядит как «событий не было» и уводит в неверный вывод. Цена — потребитель обязан знать словарь; словарь публикуется в `--help` и в сообщении об ошибке.

**D4. API — два вызова, оба чистые.**
- `std::optional<EventFilter> parse_event_filter(std::string_view spec, std::string& error)` — разбор списка: обрезка пробелов, разбиение по запятой, проверка имён по словарю, отказ на пустом списке и на неизвестном имени (текст ошибки в `error`).
- `std::vector<std::string> filter_events(const std::vector<std::string>& events, const EventFilter& filter)` — отбор с сохранением порядка исходного набора.
- `const std::vector<std::string>& known_events()` — словарь 22 имён, единый источник для проверки, сообщений и `--help`.

`EventFilter` — множество (`std::set<std::string>`): порядок результата задаёт снапшот, а не список пользователя, поэтому дубликаты в запросе схлопываются бесплатно.

**D5. Применение — в `main.cpp` сразу после `run_script`, до печати.** Мутируется только `snapshot.events`; `to_json` и `render_ascii` не меняются, поэтому остальные ключи и ASCII не затрагиваются. Флаг с `--ascii` допустим и просто ни на что не влияет.

**D6. Диагностика — через существующий `argument_error`.** Код 2, сообщение с неверным именем и перечнем допустимых; пустой список — отдельное сообщение. Взаимных исключений с другими флагами нет: единственная существующая пара — `--json`/`--ascii`.

**D7. MCP-сервер не трогаем.** `tetris_mcp.py` вызывает тот же бинарь без нового флага; расширение инструментов не входит в требования.

## Risks / Trade-offs

- [Словарь в коде разойдётся с реально порождаемыми именами] → юнит-тест, который прогоняет по одному сценарию на каждое имя из словаря и проверяет, что имя действительно появляется в `snapshot.events`; и обратная проверка — все имена из прогонов есть в словаре. **Риск реализовался при apply:** словарь, собранный по строковым литералам `clear_label`, содержал «голые» метки (`tetris`), а в снапшоте лежит `clear:tetris` — вскрылось прогоном партии и закрыто тестом на реальном сценарии с `clear:tspin_mini`.
- [Добавление нового события в ядро теперь требует правки словаря, иначе фильтр его отвергнет] → это осознанный контракт: словарь становится публичной поверхностью, а тест покрытия ловит расхождение на сборке.
- [Публичный список имён в `--help` удлиняет справку] → список печатается одной строкой, сгруппированной по источнику (управление / фиксация и линии).
- [Пользователь ожидает «фильтр по типу», например `clear`] → в спеке зафиксированы только точные имена; группы — отдельное изменение, если понадобятся.

## Migration Plan

Миграция не требуется: флаг аддитивный, поведение по умолчанию не меняется, откат — удалить флаг и модуль. Проверка после внедрения: `make test` (юнит-тесты) и `make sim` с `--events` на двух сценариях (тетрис и обычная фиксация).
