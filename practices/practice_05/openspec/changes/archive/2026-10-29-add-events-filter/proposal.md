# Proposal

## Why

Headless-прогон возвращает в JSON все события последнего действия сразу, а агенту или скрипту почти всегда нужно одно-два: был ли тетрис, сработал ли tspin, закончилась ли партия. Сейчас это выясняется разбором массива на стороне потребителя, а в ASCII-выводе событий нет вовсе, поэтому быстрый ответ «что произошло» требует внешнего разбора JSON.

## What Changes

- Новый флаг CLI `--events <список>`: печатает в снапшоте только перечисленные события (`"events": ["clear:tetris"]`), остальные ключи JSON не меняются.
- Имя события — ровно та строка, что лежит в `events`: действия без префикса (`hard_drop`, `hold`, `left`…), события линий с префиксом `clear:` (`clear:single`, `clear:tetris`, `clear:tspin_mini`…) и мета-события (`combo`, `b2b`, `perfect_clear`); всего 22 имени, полный список печатается в `--help` и в тексте ошибки.
- Список — имена событий через запятую, пробелы вокруг запятых допускаются; порядок в выводе совпадает с порядком в снапшоте, дубликаты в списке не дублируют элементы; регистр имён значим.
- Неизвестное имя в списке или пустой список — ошибка аргументов (код 2) с перечнем допустимых имён; прогон не выполняется, как сейчас устроено для неизвестного токена `--script`.
- Отсутствие совпадений — не ошибка: `"events": []`, код 0. Пустой набор легален, потому что события описывают только последнее действие.
- Без флага вывод не меняется байт-в-байт (обратная совместимость).
- Логика фильтрации выносится в ядро отдельной функцией, чтобы её покрывали юнит-тесты, а не только ручной прогон.

Не входит в изменение: новые события и изменение их генерации, фильтрация в ASCII/SDL, фильтр по категориям или подстрокам, расширение MCP-инструментов, изменения формата остальных ключей JSON.

## Capabilities

### New Capabilities
- `event-reporting`: какие события прогона попадают в снапшот и как потребитель может запросить подмножество событий через CLI.

### Modified Capabilities
(нет: раньше специфицированного поведения для событий в проекте не было)

## Impact

- `src/main.cpp` — разбор флага `--events`, справка `--help`, коды ошибок аргументов.
- `include/tetris/core/` и `src/core/` — новая чистая функция фильтрации событий (объявление и реализация рядом с существующими действиями/событиями).
- `tests/` — юнит-тесты функции фильтра; CLI-контракт проверяется прогонами `make sim`.
- `src/core/serialize.cpp` — без изменения формата: фильтр применяется до печати.
- `Makefile` — без новых целей; проверка остаётся `make test` + `make sim`.
- MCP-инструменты (`mcp_server/tetris_mcp.py`) не меняются: они используют тот же headless-вывод без нового флага.
