# Общий контракт: подтверждение перезапуска по клавише R

Статус: согласован двумя командами до написания кода.
Участники: КОМАНДА 1 (спека UI) — `spec-ui.md`, КОМАНДА 2 (спека логики) — `spec-logic.md`.
Версии «до» согласования: `spec-ui.before.md`, `spec-logic.before.md`.

Предмет: одиночное нажатие R больше не сбрасывает идущую партию мгновенно. Первое нажатие открывает окно подтверждения на 2000 мс, повторное R внутри окна перезапускает партию с тем же seed, истечение срока или любое другое действие отменяет окно без потери состояния партии.

## 1. Границы владения

| Что | Владелец | Как взаимодействуют |
|---|---|---|
| Окно подтверждения, его таймер, правила открытия/подтверждения/отмены | Логика (новый модуль ядра, собирается в `tetris_tests`, без SDL) | отдаёт UI состояние и итог шага |
| Пауза партии | UI (как и сейчас) | передаётся в логику фактом «пауза включена» каждый кадр |
| Сброс партии | Ядро `Game::reset(seed)` | вызывается UI только по итогу `confirmed`, сид берётся из снапшота до сброса |
| Файл рекорда и флаг «рекорд за партию записан» | UI | при подтверждении идущей партии запись не выполняется |
| Отрисовка оверлея, тексты, цвета, геометрия | UI | рисует по состоянию из логики |
| `GameSnapshot`, JSON, сценарии `--script`, MCP | не меняются | состояние окна в снапшот не попадает |

## 2. Состояние подтверждения (логика → UI)

Передаётся отдельной структурой, не через `GameSnapshot`:

- `active` — окно открыто (булев);
- `remaining_ms` — остаток срока, целое 0..2000 (0 при закрытом окне);
- `progress` — остаток / 2000, вещественное 0.0..1.0;
- `window_ms` — длительность окна, всегда 2000;
- `source` — откуда открыто: `game` (идущая партия) или `pause` (из паузы);
- `last_close_reason` — `none` | `confirmed` | `player_action` | `pause` | `timeout` | `game_over` | `focus_lost`.

## 3. Вход шага (UI → логика), ровно один вызов на отрисованный кадр

- `delta_ms` — прошедшие миллисекунды кадра, целое ≥ 0 (из существующего дельта-счётчика SDL-цикла);
- `r_pressed` — нажатие R только с `event.key.repeat == 0`; несколько нажатий в одном кадре сводятся к одному;
- `action_key_pressed` — нажата любая игровая клавиша (влево/вправо/повороты/софт-дроп/хард-дроп/hold/P), и она НЕ применена к партии;
- `pause` — партия сейчас на паузе;
- `game_over` — партия завершена;
- `focus_lost` — окно потеряло фокус в этом кадре.

Вызов выполняется и в игре, и в паузе, и на экране game over: иначе таймаут окна не отсчитывается.

## 4. Итог шага (логика → UI)

Одно из: `none` | `opened` | `confirmed` | `cancelled` | `expired` | `ignored`.
Единственный сигнал к сбросу партии — `confirmed`. UI не держит собственного таймера подтверждения и не решает, снимать ли окно.

## 5. Согласованные правила

1. Окно живёт 2000 мс от кадра, в котором пришло нажатие R; время реальное, не тики и не кадры.
2. Минимальный интервал между нажатиями R — 50 мс (антидребезг); нажатие раньше даёт `ignored` и окно не продлевает.
3. Открытие: R при идущей партии или при паузе. При game over окно не открывается — сразу `confirmed`.
4. Подтверждение: R внутри окна (при накопленных ≥ 50 мс) — `confirmed`, партия сбрасывается тем же сидом до состояния, побайтово равного `Game(seed)`.
5. Отмена: игровая клавиша (включая P и Esc/Q-выход не считается отменой — это выход), истечение 2000 мс, переход в game over, потеря фокуса.
6. Нажатые во время окна игровые клавиши проглатываются: партия не сдвигается, пауза не переключается.
7. Пока окно активно, игровое время стоит: UI не продвигает тики, гравитация не идёт.
8. Отмена из паузы возвращает паузу; подтверждение из паузы снимает паузу и запускает новую партию.
9. Рекорд не пишется при подтверждении идущей партии; после game over запись уже произошла, UI сбрасывает свой флаг «записан» при перезапуске.
10. Тексты оверлея — `RESTART` и `PRESS R AGAIN`, только символы встроенного шрифта 3x5 (`A–Z`, `0–9`, пробел, `-`, `:`).
11. Подсказка `R RESTART` добавляется в блок управления боковой панели рядом с существующей `P PAUSE`.
12. Headless/JSON/MCP не меняются: состояние окна не попадает в снапшот, нового токена сценария нет (`R` уже занят движением вправо).

## 6. Спорные пункты и принятые решения

| # | Вопрос | Спека UI | Спека логики | Решение |
|---|---|---|---|---|
| 1 | R при активной паузе | открывает окно (FR-002, FR-011, S-08) | игнорируется (FR-008) | **Открывает окно с `source = pause`.** Отмена возвращает паузу, подтверждение снимает паузу. Изменена спека логики: модель состояния, FR-001, FR-008 |
| 2 | Что происходит с игровым действием, нажатым при окне | клавиша проглатывается, действие не применяется (FR-016) | действие применяется как обычно (FR-006) | **Проглатывается.** Вход шага получает факт `action_key_pressed` без применения. Изменён FR-006 спеки логики |
| 3 | Включение паузы при открытом окне | P проглатывается (S-07) | пауза закрывает окно (FR-008) | **Пауза не может включиться, пока окно открыто**: P — обычная игровая клавиша. FR-008 переписан |
| 4 | Где живёт состояние окна | предполагалось в снапшоте (п. 7 данных от логики) | отдельная структура, снапшот не меняется (FR-021) | **Отдельная структура модуля**, `GameSnapshot`/JSON не трогаем |
| 5 | Полоса прогресса | не добавляется (Assumptions) | `progress` передаётся (FR-012) | **Данные передаются, отрисовка полосы не обязательна**: UI может не рисовать её, требование FR-007..FR-009 остаётся в силе |
| 6 | Потеря фокуса окна | снимает окно (FR-020) | о фокусе не знает | **Новый факт `focus_lost`** во входе шага; логика закрывает окно с причиной `focus_lost` |

## 7. Что меняется в каждой спеке после согласования

Спека логики (`spec-logic.md`):
- модель состояния: у ожидания появился источник (`game` / `pause`), добавлен переход «R при паузе» и причина закрытия `focus_lost`;
- FR-001: открытие окна и при паузе;
- FR-006: игровое действие отменяет окно и не применяется;
- FR-008: пауза не включается при открытом окне; окно из паузы при отмене возвращает паузу;
- FR-012: в состояние для UI добавлен `source`;
- FR-011: во вход шага добавлены `action_key_pressed` и `focus_lost`.

Спека UI (`spec-ui.md`):
- п. 7 «данные от логики»: состояние окна приходит отдельной структурой, а не из снапшота;
- FR-016/FR-020 уточнены как проглатывание клавиши и отправка факта `focus_lost`;
- FR-005/F-018 подтверждены как единственный владелец паузы.

История: спеки «до» — файлы `*.before.md`, сдача требует обе версии.
