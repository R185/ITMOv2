# Phase 0 — Research: подтверждение перезапуска по R

Дата: 2026-10-29. Ветка: `practice_05`. Источник: код репозитория (проверено чтением, не по памяти).

## R1. Где сейчас обрабатывается R

`src/ui/sdl_app.cpp`, функция `handle_event`: `case SDLK_r:` выполняет
`game.reset(game.snapshot().seed); paused = false;` — мгновенный сброс без подтверждения.
Вывод: точка расширения одна, и она в UI-слое, а не в ядре.

## R2. Есть ли в ядре пауза

`include/tetris/core/game.hpp` и `GameSnapshot` не содержат признака паузы: пауза — локальная
переменная `bool paused` в `run_sdl`. Вывод: окно подтверждения не может опираться на ядро в
вопросе паузы; пауза приходит фактом кадра.

## R3. Как устроен игровой цикл и время

Там же: `Uint32 frame_start = SDL_GetTicks();`, дельта кадра считается как
`now - frame_start`, гравитация аккумулируется в `double tick_accumulator` с ограничением
«не более пяти тиков за кадр». Вывод: единственный источник времени для окна — эта дельта;
свой таймер модулю не нужен, и он остаётся детерминированным в тестах.

## R4. Автоповтор клавиш

SDL присылает повторные `SDL_KEYDOWN` с `event.key.repeat != 0`. Текущий код использует их для
удержания стрелок. Вывод: нажатием R считается только `repeat == 0`; удержание не подтверждает
сброс и не продлевает окно.

## R5. Оверлеи и шрифт

`draw_message_overlay(renderer, layout, title, color, subtitle)` рисует две строки. Шрифт 3x5
содержит `A–Z`, `0–9`, пробел, `-`, `:` — строчных букв нет. Вывод: тексты окна обязаны быть
заглавными и без пунктуации вне этого набора: `RESTART`, `PRESS R AGAIN`.

## R6. Рекорд

`load_best_score()` при старте, флаг `best_recorded` — «записывается один раз за партию».
Вывод: при подтверждении сброса UI сбрасывает `best_recorded = false`, иначе рекорд новой
партии не запишется; прерванная партия в файл не попадает.

## R7. Тестовая сборка

`CMakeLists.txt`: `file(GLOB_RECURSE TETRIS_TEST_SOURCES CONFIGURE_DEPENDS "tests/*.cpp")` —
новый файл тестов подхватывается без правки CMake; `tetris_tests` не линкуется с SDL,
`add_test(NAME core ...)`. Вывод: политику окна надо держать в ядре, иначе её нельзя покрыть
тестами; UI-обвязка проверяется только сборкой и запуском.

## R8. Влияние на headless и MCP

Headless-печать (`src/core/serialize.cpp`) и MCP-сервер (`mcp_server/tetris_mcp.py`) читают
`GameSnapshot` и сценарные токены. В спеке логики зафиксировано: состояние окна не попадает в
снимок, токен `R` не переиспользуется (он уже означает «вправо»). Вывод: регрессия проверяется
побайтным сравнением JSON и ASCII с эталоном.

## Итоговые решения фазы 0

| Вопрос | Решение | Основание |
|---|---|---|
| Где живёт политика окна | Новый модуль ядра `RestartGuard` | R7: иначе непроверяемо |
| Откуда время | Дельта кадра от UI, `int delta_ms` | R3 |
| Как считается нажатие | `repeat == 0`, несколько нажатий в кадре → одно | R4 |
| Тексты | `RESTART` / `PRESS R AGAIN` | R5 |
| Пауза | Факт кадра, владелец — UI | R2 |
| Рекорд | Сброс `best_recorded` после подтверждения | R6 |
| Headless/MCP | Без изменений, регрессия побайтно | R8 |
