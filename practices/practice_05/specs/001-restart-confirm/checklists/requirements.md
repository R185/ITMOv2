# Requirements Checklist: подтверждение перезапуска по клавише R

**Purpose**: проверка качества требований двух спек и их согласованности — не проверка кода.
**Created**: 2026-10-29
**Feature**: `specs/001-restart-confirm/spec-ui.md`, `spec-logic.md`, `contract.md`

**Review Ownership**: артефакт ревьювера; `[x]` — критерий проверен и выполнен на уровне
требований, а не реализации.

## Полнота и однозначность

- [x] CHK001 Каждое требование UI (FR-001…FR-028) и логики (FR-001…FR-023) имеет одно
      прочтение: спорные места разрешены контрактом, а не «догадкой исполнителя».
      Комментарий: шесть расхождений зафиксированы явно (решения №1–№6).
- [x] CHK002 Для каждого правила есть владелец: пауза — UI, окно и срок — ядро, рекорд — UI,
      сброс партии — ядро по сигналу UI. Ссылка: `contract.md`, раздел «Границы владения».
- [x] CHK003 Ни одно требование не задаёт поведение «по усмотрению»: все границы числовые
      (2000 мс, 50 мс, ⩾ / < ).
- [x] CHK004 Термины используются единообразно: «окно подтверждения», «источник открытия»,
      «причина закрытия»; синонимы («оверлей», «попап») вне спеки логики не встречаются.

## Проверяемость

- [x] CHK005 У каждой пользовательской истории есть независимый тест или сквозной сценарий
      (US1 — `restart.*`, US2 — отмены, US3 — game over, US4 — пауза, US5 — контракт).
- [x] CHK006 Критерии успеха измеримы: срок окна в мс, число нажатий, равенство JSON после
      сброса, отсутствие изменений в headless-выводе.
- [x] CHK007 Сценарии Given/When/Then покрывают все переходы модели состояний из
      `data-model.md` (открытие, подтверждение, истечение, отмены, game over).
- [x] CHK008 Негативные случаи описаны: неизвестная клавиша, удержание R, отрицательная дельта
      времени, потеря фокуса, нажатие в один кадр с открытием.

## Согласованность артефактов

- [x] CHK009 Спека UI и спека логики не противоречат друг другу после согласования;
      расхождения версий «до» видны в `spec-*.before.md`.
- [x] CHK010 Требования не меняют унаследованный контракт: `GameSnapshot`, JSON, сценарные
      токены и MCP остаются прежними (SC спеки логики и `contracts/restart-guard.md`).
- [x] CHK011 План (`plan.md`) не вводит сущностей, которых нет в спеке и модели данных.
- [x] CHK012 Задачи (`tasks.md`) покрывают все требования: обратная трассировка есть в
      `analysis.md`.

## Границы и допущения

- [x] CHK013 Допущение «пауза — состояние UI» зафиксировано явно и не выдается за факт ядра.
- [x] CHK014 Допущение «на экране game over подтверждение не нужно» обосновано: партию уже
      нельзя потерять.
- [x] CHK015 Ограничение «состояние окна не попадает в снимок» проверяемо: сравнение JSON
      побайтно.
- [ ] CHK016 Требование «поведение подтверждено ручной проверкой в окне» не выполнено:
      сессия без дисплея. Заменено юнит-тестами политики и запуском SDL-цикла под dummy-драйвером.

## Приоритезация

- [x] CHK017 У историй расставлены приоритеты, и MVP определён: без US1 (двойное R) фича
      бессмысленна, остальные — защита от случайных действий.
