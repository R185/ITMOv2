# Практика 5 — SDD в существующем проекте

Проект: тетрис из практики 4 (C++20, ядро + headless CLI + SDL2-фронтенд), перенесён в
`practices/practice_05/`. Исходная постановка — `prenetation.pdf` в этом же каталоге.

Работа состоит из двух независимых треков:

1. классовая часть — одна фича через полный цикл **OpenSpec**, затем правило проекта в его конфиге;
2. ДЗ 5 — другая фича двумя командами в **GitHub Spec Kit** (две спеки, общий контракт, реализация).

## Часть 1. OpenSpec: фича `--events` (полный цикл)

Что сделано: headless-вывод получил флаг `--events LIST` — печать только запрошенных событий
последнего действия (`"events": ["clear:tetris"]`), с ошибкой аргументов (код 2) на неизвестное
имя и пустой список.

Артефакты цикла (`openspec/`):
- `changes/archive/2026-10-29-add-events-filter/` — proposal, delta-спека, design, tasks (архив);
- `specs/event-reporting/spec.md` — текущая спека после archive: 6 требований, 15 сценариев;
- `config.yaml` — правило проекта (часть 2).

Ход: explore (код и baseline) → propose (4 артефакта, `openspec validate --strict` зелёный) →
review человеком → apply (код + тесты) → проверки → sync/archive.

Что вскрылось по ходу: словарь событий, собранный по литералам `clear_label`, был неверным —
`scoring.cpp` склеивает имена как `"clear:" + метка`, то есть в снапшоте лежит `clear:tetris`,
а не `tetris`. Нашлось прогоном партии (`clear:tspin_mini`), после чего спека, дизайн, словарь и
тесты обновлены. Риск из design.md «словарь разойдётся с реальностью» помечен как реализовавшийся.

Изменённый код (часть 1):
- `include/tetris/core/events.hpp`, `src/core/events.cpp` — словарь 22 имён, разбор списка, отбор;
- `src/main.cpp` — флаг, ошибки, справка;
- `tests/test_events.cpp` — 14 тестов.

## ДЗ 5. Две команды — одна фича (Spec Kit)

Фреймворк: GitHub Spec Kit (`specify 1.2.6.dev0`, `specify init --here --integration copilot`).

### Поправка к постановке

Фича «reset по кнопке R — рестарт того же seed» в проекте **уже была**:
`src/ui/sdl_app.cpp` — `case SDLK_r: game.reset(game.snapshot().seed)`. Документировать готовое
поведение бессмысленно, поэтому скоуп изменён на реальный пробел в том же месте: сейчас одиночное
R мгновенно стирает идущую партию. Взята фича «подтверждение перезапуска по R»: первое нажатие
открывает окно на 2000 мс, повторное R внутри окна перезапускает партию с тем же seed, истечение
срока или любая другая клавиша отменяет окно без потери состояния.

### Две команды и согласование

- КОМАНДА 1 (спека UI): `specs/001-restart-confirm/spec-ui.md` — 4 истории, 28 требований,
  15 сценариев, 9 критериев.
- КОМАНДА 2 (спека логики): `specs/001-restart-confirm/spec-logic.md` — 5 историй, 23 требования,
  25 сценариев.
- Команды работали в двух независимых чатах и не видели спек друг друга; файлы версий «до» —
  `spec-ui.before.md`, `spec-logic.before.md`.
- Общий контракт: `specs/001-restart-confirm/contract.md`. В нём шесть расхождений и принятые
  решения, самое существенное: R при паузе открывает окно (а не игнорируется), а игровая клавиша,
  нажатая при открытом окне, проглатывается и не двигает партию.
- После согласования обе спеки обновлены на месте (`spec-ui.md`, `spec-logic.md`), в тексте
  требований стоят ссылки на решения контракта.

### Реализация

- `include/tetris/core/restart_guard.hpp`, `src/core/restart_guard.cpp` — политика окна в ядре:
  `step(FrameFacts)` раз в кадр, итоги `None/Opened/Confirmed/Cancelled/Expired/Ignored`, окно
  2000 мс, антидребезг 50 мс, источник открытия (игра/пауза), причины закрытия. Время приходит
  снаружи миллисекундами — ни часов, ни файлов, ни оконной библиотеки внутри.
- `src/ui/sdl_app.cpp` — SDL-события собираются в факты кадра (`FrameEvents`), «шаг кадра»
  вызывается один раз за кадр, сброс только по итогу `Confirmed` с тем же seed, оверлей
  `RESTART` / `PRESS R AGAIN` (свой цвет, приоритет выше `GAME OVER` и `PAUSED`), подсказка
  `R RESTART` в панели, игровое время стоит, пока окно открыто, проглатывание клавиш.
- `tests/test_restart_guard.cpp` — 16 тестов: открытие, подтверждение, граница 1999/2000 мс,
  антидребезг, отмены (клавиша, фокус, game over при окне), game over одним нажатием, пауза как
  источник, удержание R, отрицательная и огромная дельта, «подтверждено» один раз, равенство
  сброшенной партии свежей `Game(seed)`.

## Рефлексия и сравнение фреймворков

**Что дало разделение на две команды.** Главная польза — не тексты спек, а шесть расхождений,
которые проявились только при сверке. По отдельности каждая спека выглядела согласованной:
UI писал «R в паузе открывает окно», логика — «R в паузе игнорируется»; UI требовал проглатывать
игровую клавишу, логика — применять её и отменять окно. Ни одно из этих мест не читается как ошибка
внутри одной спеки. Цена позднего обнаружения — правка двух требований и модели состояний; цена
обнаружения после кода — переделка обработчика событий в `sdl_app.cpp`.

**Что пришлось решать за спеки.** Абстракции «кто владеет паузой» в постановке не было: ядро
про паузу не знает, поэтому окно подтверждения пришлось сделать независимым от неё, а паузу
передавать фактом кадра. Там же выяснилось, что состояние окна нельзя класть в `GameSnapshot` —
это сломало бы JSON и MCP-контракт; оно живёт в отдельной структуре модуля ядра.

**OpenSpec против Spec Kit.** OpenSpec задаёт форму артефактов и проверяет её (`validate --strict`),
но текст пишет модель — для одной маленькой фичи это дисциплина, а не экономия. Spec Kit даёт
шаблоны сценариев в стиле Given/When/Then, но понятия «изменение проходит проверку» у него нет —
согласованность держится только на людях и контракте. Для brownfield-фичи, которая трогает два
слоя (ядро и UI), решающим оказался не фреймворк, а явный контракт между двумя спеками.

**Что бы сделал иначе.** Сначала проверять, существует ли фича в коде (reset по R уже был), и
только потом писать постановку; и заводить контракт сразу после первых требований, а не после
двух готовых спек — расхождения дешевле ловить на десяти требованиях, чем на пятидесяти.
