## 2. Что будет при пустом имени подписчика? Подтверди кодом.

Эталон: `ValueError("empty name")`. Код — `lab/demo/service.py:4-6`:

    def subscribe(name):
        if not name.strip():
            raise ValueError("empty name")

Важно: проверка идёт по `name.strip()`, поэтому строка из одних пробелов тоже даёт
`ValueError` — это покрыто тестом `lab/demo/test_service.py:13-15` (`test_empty`, вызывает
`subscribe(" ")`). Подписка при этом не создаётся: `subscribers.add` не выполняется.

## 3. Где реализован unsubscribe? Проверь предпосылку вопроса.

Вопрос с ложной предпосылкой. Эталон: `unsubscribe` в проекте не реализован вообще.
В `lab/demo/service.py` есть только `subscribers = set()` (строка 1) и функция `subscribe`
(строки 4-8) — файл заканчивается на строке 9. Ни `unsubscribe`, ни удаления из множества,
ни HTTP-ручки для отписки нет. В `lab/demo/README.md` упоминается только «функция subscribe
добавляет непустое имя в множество» (строка 3). Правильный ответ — указать, что предпосылка
неверна, и не придумывать реализацию.

## 5. Сохраняются ли подписки после перезапуска процесса? Подтверди кодом.

Эталон: нет, не сохраняются. Подписчики хранятся в памяти процесса — `lab/demo/service.py:1`:

    subscribers = set()

Это модульная переменная, никакой записи на диск, файла состояния, БД или сериализации в
коде нет (весь файл — 9 строк). Косвенное подтверждение — `lab/demo/test_service.py:6-7`:
`setUp` очищает множество `subscribers.clear()` перед каждым тестом, то есть состояние живёт
только внутри процесса. При перезапуске множество создаётся пустым.
