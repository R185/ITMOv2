## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- OUT-1: ответ содержит summary, массив risks (≤3) и массив checks; элементы risks: file, line, evidence, risk.
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub.
- QA-1: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.
- OBS-1: в лог пишутся только request_id, длительность и статус. Содержимое diff и ответа модели не логируется.

### Формат входа и результата

- Вход: строка diff (текст PR), возможно с чувствительными данными; объём ≤ 20 000 символов.
- Результат: JSON со структурой { summary, risks: [{file, line, evidence, risk}], checks: string[] }.

### Ограничения и запрещённые действия

- Таймаут LLM-вызова 10 секунд; по таймауту/ошибке вернуть контролируемый ответ (REL-1).
- Не пересылать секреты во внешний LLM; сначала редактировать/редактировать [REDACTED] (SEC-1).
- Отклонять избыточный вход с 413, не пытаться его сокращать автоматически (API-1).
- Не выполнять approve/merge и не изменять код (SCOPE-1).
- Логировать метаданные без содержимого (OBS-1).

### Хороший пример


app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED].

### Плохой пример


Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Точный перечень паттернов секретов для редактирования; требуемая аутентификация и rate limiting для API.

## Как использовали AI

- Для чего: собрать Context Pack и проверить соответствие правилам CASE.md по TRAINING_PR.diff
- Тип промпта: сначала zero-shot (P1-01), затем master prompt (P1-02)
- Строка в [`prompts.md`](prompts.md): см. записи P1-01 и P1-02
- Что проверили и исправили сами: сопоставили риски с конкретными строками diff и правилами; оформили проверяемые сценарии
