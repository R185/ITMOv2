# Практика 8 — отчёт

**Проект:** Bug Triage Console — интерфейс к автоматическому разбору багов из практик 7.1/7.2.
**Стек:** React 18 + TypeScript + Vite, Material UI 6, сервер на Node (статика + прокси к GitHub),
тесты Vitest + Testing Library + MSW.

Репозиторий практики: `practices/practice_08/` (ветка `practice_08`). Инструкции по запуску —
`app/README.md`.

**Живая ссылка:** https://rreflector.com/bugs/ — приложение работает с настоящим GitHub API
(скриншот `evidence/ui-05-deployed.png`).

## Основной сценарий

Разработчик открывает консоль, видит список баг-репортов со статусами, заполняет форму
(заголовок + шаги воспроизведения) и отправляет. Репорт уходит в GitHub как issue с лейблом `bug`,
сразу появляется первым в списке со статусом «Открыт», форма очищается. Дальше его подхватывает
пайплайн из 7.2: классификация → патч → PR → AI-ревью → мерж; статус в списке меняется на
«В работе» (PR открыт) и «Исправлен» (PR смержен).

## AI и правки

- Макет: AI сгенерировал пять фреймов и тексты ошибок; я убрал лишний экран «подтверждение» —
  в сценарии нет второго шага, и добавил состояние «загрузка списка» (скелетоны), которого не было.
- Интерфейс: AI собрал компоненты и тему; правки — статус «В работе» должен был учитывать только
  открытые и смерженные PR (закрытый PR без мержа показывал ложное «в работе»), и валидация
  продублирована на сервере, чтобы обойти её в обход формы было нельзя.
- Тесты: AI предложил проверки «элемент отрисован» и «кнопка существует»; я заменила их на
  проверки видимого результата (карточка в списке, текст ошибки, число POST-запросов) и добавила
  MSW-сценарии с задержкой и ошибкой.

## Оговорки

- Деплой сделан через Caddy (`docs/Caddyfile.snippet`): `/bugs/*` → 127.0.0.1:8787, остальное — n8n.
  Маршрут живёт в рантайме Caddy; чтобы он сохранился после перезапуска, нужно один раз выполнить
  `sudo bash /tmp/root_setup.sh` (кладет Caddyfile на диск).
- Скриншоты сняты с настоящего API; пустое состояние и задержка проверены тестами, а не скриншотом.
