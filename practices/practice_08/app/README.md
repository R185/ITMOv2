# Bug Triage Console — приложение

Фронтенд к проекту курса: интерфейс к автоматическому разбору багов из практик 7.1/7.2.
Пользователь отправляет баг-репорт → он уходит в GitHub как issue с лейблом `bug` → в списке
видно этап: открыт, в работе (есть PR), исправлен (PR смержен).

## Библиотека компонентов

Material UI 6 (`@mui/material`) — кнопки, текстовые поля, карточки, чипы, скелетоны, снэкбар.
Тема одна на всё приложение: `src/theme.ts` (палитра, типографика, радиусы, отступы через `spacing`).

## Сценарий

1. Экран открывается, список репортов грузится с реального API.
2. Пользователь заполняет заголовок и шаги воспроизведения, отправляет форму.
3. Пока идёт запрос — кнопка и поля disabled, повторный submit отсекается флагом `inFlight`.
4. Репорт появляется первым в списке со статусом «Открыт», форма очищается, показывается тост.

## Запуск

```bash
npm install        # зависимости
npm run build      # сборка (tsc -b + vite build)
cd ../server && node index.mjs   # статика + прокси к GitHub API
# → http://127.0.0.1:8787
```

Токен берётся из `GITHUB_TOKEN` или из `~/.config/gh/hosts.yml` (как у `gh`), в браузер не попадает.
Репозиторий задаётся переменной `REPO` (по умолчанию `R185/itmo-ai-practice-07`).

Разработка: `npm run dev` — Vite проксирует `/api` на `127.0.0.1:8787`.

## Тесты

```bash
npm test
```

Vitest + Testing Library + MSW. Покрыто: загрузка списка, пустое состояние, ошибка загрузки с
повтором, валидация полей, создание репорта, двойная отправка во время ожидания, ошибка сервера
с повтором, подписи полей и клавиатурный фокус.

## Структура

```
src/            React + TypeScript
src/components/ BugReportForm, IssueList, StatusChip

src/__tests__/  клиентские тесты
../server/      Node-сервер: статика и прокси к GitHub (токен только на сервере)
../docs/mock.html  макет из пяти фреймов
```
