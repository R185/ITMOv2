## Эксперимент: Техника Few-Shot для артефакта "tests_load.md"
**Что делали:** Взяли исходный tests_load.md и подготовили файл few_shot/tests_load.md с примерами для инженеров: добавили шаблон строки таблицы, хорошие и плохие примеры, чек-лист и шаблон промпта.
**Примеры, которые использовали:**
1. Шаблон строки: фиксирует поля, единицы измерения, фазы (прогрев/стабильная фаза) и требования к Evidence.
2. Массовые запросы с малым diff: 50 RPS; 5 минут; пороги ошибок ≤ 1%, p95 ≤ 500 мс, p99 ≤ 900 мс; метрики CPU/latency/таймауты; Evidence — отчёт k6 и снапшот Grafana.
3. Чтение из кэша (холод → тёплый): ramp-up 0→200 RPS за 2 мин; 1 мин прогрев + 10 мин стабильной фазы; ошибки ≤ 0.5%; p95 ≤ 150 мс; cache hit ≥ 90%; Evidence — Gatling + панель Redis.
4. Пиковые записи в БД: 80 RPS; 2 мин прогрев + 15 мин; ошибки ≤ 1%; p95 ≤ 300 мс; p99 ≤ 600 мс; CPU БД ≤ 70%; Evidence — CI artefact + дашборд PostgreSQL.
5. Всплеск одновременных пользователей: 500 VUs; спайк 30 с + стабилизация 12 мин; ошибки ≤ 1%; p95 ≤ 400 мс; метрики saturation/очереди/GC; Evidence — Gatling отчёт + профилирование.
6. Плохие примеры: «Большая нагрузка», «Тест БД», «Пользователи» — иллюстрируют ошибки: отсутствие единиц/фаз, нечёткие пороги, невалидный Evidence.
**Результат:** few_shot/tests_load.md содержит практические ориентиры: шаблон, хорошие/плохие примеры, чек-лист и промпт. Это ускоряет добавление новых сценариев и повышает качество артефакта.
