# Tree of Thoughts

- Решение, для которого нужны альтернативы: переработать файл нагрузочного тестирования в контексте Tree of Thoughts.
- Критерии выбора: полезность для инженера, сохранение исходных данных, сложность реализации.

## Запрос

Переработать `tests_load.md` для папки `practice_02/tree_of_thoughts/`, применив технику Tree of Thoughts: сгенерировать 3 ветви (А — минимальные правки, Б — преобразование в Decision Tree, В — добавить альтернативные сценарии), оценить их и выбрать лучшую; на основе выбора создать `tests_load.md`; описать эксперимент в `experiment.md`.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A: Минимальные правки | Максимально сохраняет исходник; быстро применить; низкий риск | Малопригодно для пошаговых решений; слабая навигация по исходам | Полезность: средняя; Сохранение: высокое; Сложность: низкая |
| B: Decision Tree | Ведет инженера по решениям и развилкам; хорошо масштабируется; снижает флейки | Чуть выше трудоемкость; нужно аккуратно перенести все метрики | Полезность: высокая; Сохранение: высокое; Сложность: средняя |
| C: Альтернативные сценарии | Раскрывает покрытие; даёт выбор подходов под разные стрессы | Риск раздувания объема; сложнее поддержка и согласование SLO | Полезность: средняя-высокая; Сохранение: среднее; Сложность: средняя-высокая |

## Выбор

- Выбранная альтернатива: B — Decision Tree.
- Почему: максимальная полезность для инженера при сохранении исходных метрик и требований; превращает список в пошаговую процедуру с развилками Pass/Fail и корректирующими действиями.
- Как проверим: сравним, что все поля исходной таблицы сохранены (сценарий, нагрузка, пределы, что измеряем, evidence); проведем dry-run на тестовом стенде и убедимся, что по дереву можно принять решение без дополнительных договоренностей.
