## Внешние стандарты и практики (для контекстуализации метрик)

- Google SRE Book — Service Level Objectives: использование перцентилей p95/p99 для латентности как стандартной SLI-практики. https://sre.google/sre-book/service-level-objectives/
- RFC 2330 — Framework for IP Performance Metrics (IPPM): терминология и подходы к измерениям задержек и потока. https://www.rfc-editor.org/rfc/rfc2330
- Grafana k6 Thresholds: определение порогов по перцентилям, например `p(95) < 500ms`, что соответствует указанному «p95 latency ≤ 500 мс». https://grafana.com/docs/k6/latest/using-k6/thresholds/
- Gatling Percentiles: поддержка p95/p99 в отчётах и проверках производительности. https://gatling.io/docs/gatling/reference/current/core/results/percentiles/

Примечание: «LLM-тупики» — доменная оговорка исходного артефакта о недопустимости зависаний/блокировок на стадии LLM; внешних формализованных стандартов для этого термина нет, он фиксируется как внутренняя нефункциональная проверка.
